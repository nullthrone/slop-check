# Architecture

This document is the contract between all parts of the repository. Anything that
crosses a directory boundary (file formats, CLI commands, function signatures,
workflow names) is defined here. If code and this document disagree, fix one of
them in the same pull request.

## 1. Decisions

| # | Decision | Consequence |
|---|----------|-------------|
| D1 | Pattern and source data are YAML files in this repository, validated against JSON Schemas. Generated packages and bot-written data live outside `main` (branches `dist` and `data`). | Git history is the change log; files carry no history of their own. |
| D2 | Findings describe style patterns. They never claim that a text was written by an AI. | Report wording, skill instructions and docs avoid authorship claims. |
| D3 | Each pattern carries its own detection rule (`threshold`), weight (measured) and optional dependency (`requires`). | A contributor states when a pattern counts and what it depends on; the measurement decides how much it weighs. |
| D4 | Operational definition: a slop pattern is a pattern that is over-represented in LLM output relative to a human baseline. | Admission to the scored core is decided by measurement. Sources make a pattern a candidate; they do not make it core. |
| D5 | Lifecycle `observation -> candidate -> core -> fading`. `core` and `fading` are derived from measurements and never declared by contributors; the only declared core patterns are the initial core (5.3). | A contributor cannot self-promote a pattern. |
| D6 | Four modes: `audit` (default), `rewrite` (surgical, diff), `prevent` (rules applied while generating), `batch` (deterministic CLI with exit code and JSON). | One engine serves batch and audit; rewrite and prevent are skill-mode only. |
| D7 | Model-agnostic skill in the open Agent Skills format (`SKILL.md` + `references/` + optional `scripts/`). The same package runs in Claude, the Gemini app, Gemini CLI and other skill-capable agents. Scripts accelerate, they are never required, and neither are the reference files: the packaged `SKILL.md` alone suffices for a correct audit. | No vendor-specific tool names or prompt idioms in skill text. Package must satisfy the strictest known runtime (section 7). |
| D8 | Multimodal: text is fully cataloged in v1. Image and web page patterns ship as `candidate` (audit runs, no score weight) plus prevention rules for image generation and for building web pages. Web patterns cover the design and markup of a page; its copy stays a text audit. Schema reserves `code`, `audio`, `video`. | Image and web prevention work immediately (e.g. Gemini image generation, a coding assistant building a landing page); scoring them waits for an image or web benchmark. |
| D9 | Score plus traffic light. Findings sorted by weight, a score (sum of weights of triggered scored patterns) and a verdict GREEN / YELLOW / RED derived from the score. | CLI exit codes hang on the verdict. |
| D10 | Autonomous quality gate. Content pull requests merge automatically when all checks pass. Maintainer review is required only for changes to the gate itself (workflows, engine, eval code, thresholds, skill instructions), enforced by CODEOWNERS. | No routine review load for the maintainer. |
| D11 | Gate measurements use data the contributor does not control: a human corpus written before November 2022 and an AI corpus generated by CI. Contributor-supplied examples are necessary but never sufficient. | Prevents benchmark saturation through self-chosen fixtures. |
| D12 | LLM calls go through OpenRouter with one key (`OPENROUTER_API_KEY`). Hard monthly cap 25 EUR, enforced in code. | One secret, any model family. |
| D13 | Repository language is English. Examples, word lists and regexes live in their own language. v1 ships `de` and `en` realizations; language-agnostic patterns (`*`) apply to every language. | Contributors can add a language by adding realizations. |
| D14 | The weekly research routine opens pull requests against this repository and passes the same gates as any contributor. | Research output becomes reviewable data. |
| D15 | No hard-coded model IDs. `evals/models.yaml` holds selection rules; a weekly resolver picks concrete OpenRouter models and writes a lockfile to branch `data`. | Renamed, added or retired models are picked up without a code change; every measurement records the exact `canonical_slug` it used. |
| D16 | The project's home is the `nullthrone` organization: repository `github.com/nullthrone/slop-check`, site `nullthrone.github.io/slop-check`. | Links between files of this repository are relative, so they work in forks and local clones. Absolute links (release downloads, site, issues) point to the canonical home, also inside forks. `ci.yml` runs in any repository context; workflows that publish, deploy, write bot branches, spend budget or run on a schedule (`llm-eval`, `automerge`, `measure`, `models`, `conformance`, `release`, `pages`) run only when `github.repository == 'nullthrone/slop-check'`, so forks stay quiet. |

## 3. Pattern format

Full schema: `schema/pattern.schema.json`. Example: `patterns/text/antithesis-template.yaml`.

```yaml
id: antithesis-template          # kebab-case, unique, immutable, <= 64 chars
modality: text                   # text | image | web | code | audio | video
name: Antithesis template
summary: >                       # the mechanism, in English
  ...
category: rhetoric               # see schema enum
status: core                     # observation | candidate | core (core only for the initial core, 5.3)
detector:
  kind: regex                    # regex | lexicon | metric | llm | vision
  position: any                  # any | text_start | paragraph_start | paragraph_end | last_paragraph | sentence_start
  metric: null                   # metric name, only for kind: metric (section 4.3)
  params: {}                     # metric parameters
  rubric: null                   # judging instruction for kind llm/vision (English)
threshold:
  min_count: 1                   # hits needed
  per_words: null                # if set: density = hits / words * per_words, compared with min_count
  comparison: gte                # gte | gt
  scope: text                    # text | paragraph (trigger if any single paragraph reaches min_count)
  short_text: {min_count: 1}     # override for texts <= governance short_text_max_words
  value: null                    # metrics: {op: lt|lte|gt|gte, x: <number>}
  min_units: null                # metrics: minimum sentences/paragraphs for the metric to apply
  min_words: null                # minimum words of analyzed text for the rule to apply
  context_overrides:             # optional, keyed by context (default|informal|technical|academic|marketing)
    informal: {min_count: 2}
requires: null                   # {min_other_findings: 3}: counts only if >= 3 other scored patterns triggered
realizations:                    # keyed by language subtag or "*"
  en:
    patterns: ["(?i)..."]        # regex detector payload (Python re syntax)
    terms: []                    # lexicon detector payload; trailing * = prefix match
    examples:
      positive: ["..."]          # detector must produce >= 1 hit on each
      negative: ["..."]          # detector must produce 0 hits on each
    test_texts:                  # optional, full-threshold checks
      - {text: "...", expect: trigger}
  de: {...}
legitimate_use: >                # when a hit is NOT slop (guides the host model in skill mode)
fix: >                           # correction guidance (audit suggestions, rewrite mode)
prevention: >                    # imperative rule for generation time (prevent mode)
sources:
  - {source: tropes-fyi, locator: "entry 'Negative parallelism'", note: "..."}
related:
  - {id: german-stock-phrases, relation: overlaps}
```

YAML loaders convert date values to ISO strings (`YYYY-MM-DD`) before schema validation,
so contributors can write unquoted dates.

A density (`per_words`, or a metric that counts per words such as `em_dash_density`) is noise over
a few dozen words: two nominalizations in a 22-word text give 27 per 300 words. Patterns with a
density rule therefore carry `short_text: {min_words: 100}`. The thresholds were calibrated on texts
of 150 words and more, which the short-text rule never touches.

Rules enforced by `slopcheck-dev validate`:

1. `status: core` requires the ID to be listed in `governance/thresholds.yaml: initial_core`.
2. `candidate` requires at least 2 independent sources (section 5.2), a detector, and per realization language at least 2 positive and 2 negative examples.
3. `observation` requires at least 1 source. Detector optional.
4. Every `source` reference resolves to `sources/<id>.yaml`.
5. Regexes compile, contain no nested unbounded quantifiers, and run on a 50 kB adversarial input in under 200 ms (subprocess with timeout).
6. Lexicon terms are unique per language.
7. `realizations` keys are language subtags (`^[a-z]{2,3}$`) or `*`.
8. File name equals `<id>.yaml` and lives under `patterns/<modality>/`.
9. `web` patterns use the detector kinds `vision` (judged from the rendered page or a screenshot) or `llm` (judged from the HTML, CSS or component source). The engine reads text only, so regex, lexicon and metric detectors cannot run on a page.

## 4. Runtime engine (`src/slopcheck`, stdlib only)

### 4.1 Public API

```python
from slopcheck.catalog import load_catalog          # (path: str | None = None) -> dict
from slopcheck.engine import analyze                 # see below
from slopcheck.report import render_markdown, render_json

result = analyze(
    text: str,
    catalog: dict,                 # catalog.json structure (section 4.4)
    lang: str | None = None,       # None = auto-detect (de/en; otherwise "und")
    context: str = "default",
    modality: str = "text",
    llm_judge: Callable | None = None,   # evaluates kind=llm patterns; None = skipped
) -> dict                          # result structure (section 4.5)
```

`load_catalog(None)` loads `catalog.json` next to the package (skill layout) or the
path in env `SLOPCHECK_CATALOG`.

`analyze` evaluates every pattern of the requested modality that has a detector,
regardless of status (measurement needs candidates too). Scoring uses only
patterns whose `effective_status` is `core`.

### 4.2 Text model

- Paragraphs: split on blank lines. Markdown headings, list items and table rows are units of their own (needed for position rules and bullet metrics). Fenced code blocks are excluded from analysis.
- Sentences: split on `.`, `!`, `?`, `…` followed by whitespace and an uppercase letter, digit or quote; abbreviation lists for de/en.
- Words: Unicode word tokens (`\w+` with apostrophes inside words).
- Language detection: stopword frequency for de/en. Below confidence: `und`; only `*` realizations run.

### 4.3 Detectors

| kind | Payload | Hit |
|------|---------|-----|
| `regex` | `realizations.<lang>.patterns` | each match, filtered by `position` |
| `lexicon` | `realizations.<lang>.terms` | each whole-word, case-insensitive match; `term*` = prefix |
| `metric` | `detector.metric`, `detector.params` | metric returns `value` and evidence spans; trigger via `threshold.value` |
| `llm` | `detector.rubric` + examples | via `llm_judge`; skipped (listed under not evaluated) without one |
| `vision` | `detector.rubric` | image and web modality; evaluated by the host model or an eval judge |

`min_units` (sentences or paragraphs, in the detector's unit) and `min_words` (words of analyzed
text, `slopcheck.thresholds.words_ok`) are preconditions of every rule: below them a pattern never
triggers, an aggregate metric reports no hits and an `llm` pattern is not sent to the judge. The
threshold text names them (`at least 3 sentences`, `at least 100 words`).

Regexes compile with `re.MULTILINE` (inline flags such as `(?i)` allowed). Hit quotes are
trimmed of leading and trailing whitespace and sentence punctuation. Positions are checked
on the trimmed hit start relative to its paragraph or sentence.

Metric registry (`slopcheck.metrics`), all language-aware where noted:

| metric | value |
|--------|-------|
| `em_dash_density` | em dashes (U+2014, and U+2013 used as dash between spaces) per `params.per_words` words |
| `curly_quotes` | count of U+201C/U+201D/U+2018/U+2019 outside languages listed in `params.exempt_languages` (de uses „“ legitimately) |
| `sentence_length_cv` | minimum, over runs of `params.run` consecutive paragraphs, of the coefficient of variation of sentence length; a paragraph with fewer than `params.min_sentences_per_paragraph` sentences (default 1) breaks a run |
| `emoji_decoration` | count of emoji or decorative symbols used as line prefix (bullets, headings) |
| `markdown_emphasis_density` | bold + italic + heading markers per 100 words |
| `paragraph_start_ratio` | share of paragraphs starting with a term from `realizations.<lang>.terms` |
| `nominalization_density` | nominal suffix tokens (language-specific suffix list in params) per `params.per_words` |
| `bullet_bold_lead` | max run of list items shaped `**lead**: text` (or `lead:` in bold) within one list |
| `triad` | count of three-item coordinations (`A, B(,) and/und/or/oder C`, items 1-3 words) |
| `comma_density` | commas per sentence |
| `hyphenated_premodifier_density` | hyphenated compound pre-modifiers per 100 words |

New metrics require a code change (protected path) and a schema enum entry.

### 4.4 `catalog.json`

Produced by `slopcheck-dev build`. Runtime never reads YAML.

```json

  "catalog_version": "2026.11.17",
  "generated_at": "2026-11-17T12:00:00Z",
  "short_text_max_words": 150,
  "verdict_thresholds": {"yellow": 2.0, "red": 5.0, "source": "provisional|measured"},
  "patterns": [ { "...all pattern fields...": "...", "effective_status": "core", "weight": 2.5, "weight_source": "provisional|measured|none" } ]
}
```

### 4.5 Result structure

```json
{
  "engine_version": "0.1.0",
  "catalog_version": "...",
  "verdict": "GREEN|YELLOW|RED",
  "score": 3.5,
  "verdict_thresholds": {"yellow": 2.0, "red": 5.0},
  "provisional": true,
  "words": 412, "language": "de", "context": "default", "modality": "text",
  "findings": [
    {"pattern_id": "antithesis-template", "name": "...", "effective_status": "core",
     "weight": 2.5, "count": 2, "triggered": true, "threshold": "min 1 per text",
     "hits": [{"quote": "...", "paragraph": 3, "start": 120, "end": 168}],
     "fix": "..."}
  ],
  "observations": [ "same shape: triggered candidate or fading patterns, weight 0" ],
  "not_evaluated": ["hollow-sentences"],
  "all_patterns": { "<id>": {"triggered": false, "count": 0} }
}
```

`provisional` is true if any scored weight is a provisional weight (not yet measured).

### 4.6 Report (Markdown)

Labels in `en` or `de` (`--report-lang`). Structure:

```
# Slop-Check: <title>

Verdict: YELLOW (score 3.5; yellow from 2.0, red from 5.0) | 412 words | language: de
<one-line rationale naming the heaviest findings>

## Findings (2)
1. Antithesis template (`antithesis-template`, weight 2.5): 2 hits, threshold min 1 per text
   > "..." (paragraph 3)
   Suggestion: ...

## Observations, not scored (1)
1. ... (`rhetorical-self-answer`, candidate): ...

## Not evaluated (1)
- `hollow-sentences` (requires a language model)

## Notes
<provisional weights notice if applicable>
```

The skill instructs the host model to use the same structure: `skill/SKILL.md` carries the skeleton
with English and German labels, `skill/references/report-format.md` the details and the JSON result.

### 4.7 CLI

```
slopcheck audit [PATH ...|-] [--lang de|en|auto] [--context default|informal|technical|academic|marketing]
                [--format md|json] [--report-lang en|de] [--fail-on yellow|red]
                [--catalog PATH] [--llm]
slopcheck patterns [--modality text|image|web] [--status core|candidate|observation|fading] [--format md|json]
slopcheck version
```

Exit codes: `0` ok (or verdict below `--fail-on`), `1` verdict reached `--fail-on`, `2` usage or input error.
`--llm` evaluates `kind: llm` patterns through OpenRouter if `OPENROUTER_API_KEY` is set (`slopcheck.llm`, urllib only).
In the skill package the CLI runs as `python scripts/slopcheck.py audit ...`.

## 5. Governance data

### 5.1 `governance/thresholds.yaml`

Admission thresholds, weights, provisional verdict thresholds, budget, initial core.
Protected by CODEOWNERS.

### 5.2 Source independence

Sources form clusters: two sources are in the same cluster if one lists the other in
`derived_from` (transitively) or they share the same `publisher`. Academic sources
(`academic-preprint`, `peer-reviewed`) cluster by shared authors instead, because their
publisher is the archive or venue (for example arXiv). A pattern's number
of independent sources is the number of distinct clusters among its references.
Source types: `academic-preprint`, `peer-reviewed`, `corpus-study`, `commercial-study`,
`community-directory`, `practitioner-skill`, `blog`, `press`, `documentation`, `own-observation`.
`own-observation` never counts toward independence.

### 5.3 Initial core

`governance/thresholds.yaml: initial_core` lists the patterns that start with `status: core`
and maps each to a provisional weight. The first measurement that covers such a pattern
replaces its provisional weight with a measured one or demotes it to `fading`.

## 6. Evaluation (`src/slopcheck_dev/evals`)

### 6.1 Corpora

- Human corpus: texts published before 2022-11-01, fetched at runtime from pinned public dataset revisions, never committed. Register mix: web prose (incl. marketing and blogs), encyclopedic, explanatory Q&A. Per language at least 200 documents. `corpus/human/manifest.json` on branch `data` stores references and SHA-256 hashes.
- AI corpus: generated by CI from fixed prompts in `evals/corpus/prompts/`, topic-matched to human documents (topic derived deterministically from the human document, no LLM call). Several model families (`evals/models.yaml: generators`). Stored on branch `data`.
- Split: `sha256(doc_id) % 10 < 5` is `dev` (pull request gate), the rest `holdout` (scheduled promotion).

### 6.2 Metrics per pattern and language

- `fpr_human` = triggered human documents / human documents
- `hit_ai` = triggered AI documents / AI documents, also per model family
- `lift` = (hit_ai + a) / (fpr_human + a), a = 0.5 / n_human
- Triggered means the full rule (detector + threshold + requires), computed by `slopcheck.engine.analyze`.
- `kind: llm` patterns: a hit requires agreement of both judges in `evals/models.yaml: judges`.
  Each judge receives the measured `llm` patterns whose `effective_status` is `core` and all
  other measured `llm` patterns in separate calls (at most two calls per document and judge;
  one when only one kind is measured), so a candidate rubric never shares a prompt with a
  scored pattern. This holds for the pull request gate (changed patterns only) as well. A
  document with both kinds costs two calls per judge; each call is budgeted and recorded.

### 6.3 `measurements.json` (branch `data`)

```json
{
  "measured_at": "2026-12-01T03:17:00Z",
  "corpus": {"human_docs": {"de": 200, "en": 200}, "ai_docs": {"de": 1000, "en": 1000}, "split": "holdout"},
  "verdict_thresholds": {"yellow": 2.1, "red": 5.4},
  "patterns": {
    "<id>": {
      "pattern_hash": "<sha256 of the canonical pattern JSON>",
      "per_language": {"de": {"fpr_human": 0.01, "hit_ai": 0.22, "lift": 14.3, "n_human": 100, "n_ai": 500}},
      "per_family": {"anthropic": {"hit_ai": 0.3, "lift": 18.0}},
      "fpr_human": 0.01, "hit_ai": 0.2, "lift": 12.0,
      "meets_core": true, "meets_fading": false, "weight": 2.48
    }
  }
}
```

A measurement applies to a pattern only while `pattern_hash` matches; an edited pattern
falls back to its declared status until remeasured.

### 6.4 Status derivation (`slopcheck_dev.status.derive`)

```
derive(pattern, measurement | None, thresholds) -> (effective_status, weight, weight_source)
```

| declared | measurement | effective | weight |
|----------|-------------|-----------|--------|
| observation | any | observation | 0 |
| candidate | none or not meets_core | candidate | 0 |
| candidate | meets_core | core | measured |
| core (initial) | none | core | provisional (`initial_core`) |
| core (initial) | meets_core | core | measured |
| core (initial) | meets_fading | fading | 0 |
| core (initial) | neither | core | measured |
| any measured core | meets_fading | fading | 0 |

Measured weight: `clamp(ln(lift), weights.from_lift.min, weights.from_lift.max)`.
Verdict thresholds: measured values if present (yellow = 90th percentile of human
scores, red = median AI score, both on holdout), else `verdict_provisional`.

### 6.5 Budget

`budget/ledger.json` records month, run, model, tokens, cost (from OpenRouter usage
data, else estimated from `/api/v1/models` pricing). Every privileged job checks the
month total against `thresholds.yaml: budget` before spending and aborts cleanly when
the cap would be exceeded. The run caps (`per_pull_request_usd_cap`, `per_scheduled_run_usd_cap`,
`conformance_run_usd_cap`) apply per run id, which is the workflow run and attempt; entries carry
no pull request number, so `per_pull_request_usd_cap` bounds one llm-eval run, and each push or
re-run of a pull request is a new run. Spending jobs share the concurrency group `openrouter-budget`, so
they run one at a time and read the ledger only while they hold it; the job that holds the key
never holds a token that can push, and a separate job merges its spend into the ledger. When budget
or key is missing: candidates pass the LLM gate with a notice (weight 0 anyway); changes to
effective-core `llm` patterns fail.

### 6.6 Model resolution (self-updating)

`evals/models.yaml` defines roles (`generators`, `judges`, `conformance`, `vision_judge`)
as selectors, never as fixed IDs:

```yaml
generators:
  - family: anthropic
    match: '^anthropic/claude-haiku-'      # regex on OpenRouter model id
    tier: cheap
```

`slopcheck-dev models resolve` reads `https://openrouter.ai/api/v1/models` (public, no
key) and, per selector, picks the model with the newest `created` timestamp that:
matches `match`; is not `:free`, `:batch`, `-preview`, `-exp` or a dated snapshot alias
unless the selector allows it; has the required input/output modalities (text output
for generators and judges, image input for `vision_judge`); costs at most the
selector's `max_price` per million tokens; has no `expiration_date` within 30 days.
A selector that matches nothing falls back to its `fallback_match`, then fails loudly in
the report without breaking the run.

Output `models/lock.json` on branch `data`:

```json
{"resolved_at": "...", "roles": {"generators": [{"family": "anthropic", "id": "anthropic/claude-haiku-5.5",
  "canonical_slug": "anthropic/claude-haiku-5.5-20261007", "created": 1791397883,
  "pricing": {"prompt": 1e-7, "completion": 5e-7}}]}, "changes": ["generators/anthropic: ... -> ..."]}
```

Workflow `.github/workflows/models.yml` (weekly) runs the resolver and commits the lockfile to `data`.
All other jobs read the lockfile. When a generator's `canonical_slug` changes, the next
measurement generates AI corpus documents for the new model; documents of models no
longer in the lock are kept for trend reporting but excluded from admission metrics.
Pricing for budget estimation comes from the same lockfile.

### 6.7 Dev CLI

```
slopcheck-dev validate [--changed-only BASE_REF]
slopcheck-dev check-fixtures [IDS ...]
slopcheck-dev build --out dist [--measurements PATH] [--version VERSION]
slopcheck-dev corpus fetch-human --out DIR
slopcheck-dev corpus generate-ai --human DIR --out DIR [--models ...]
slopcheck-dev measure --human DIR --ai DIR --split dev|holdout [--patterns IDS ...] [--llm] --out FILE
slopcheck-dev gate --measure FILE --patterns IDS ...          # applies PR admission rules, exit 1 on failure
slopcheck-dev guard --base BASE_REF [--measurements PATH]     # scored patterns stay gated, exit 1 on failure
slopcheck-dev conformance --skill dist/slop-check [--models ...] --out FILE
slopcheck-dev budget status|check --amount USD
slopcheck-dev models resolve [--out FILE] [--previous FILE]
```

`guard` compares the merge base of `BASE_REF` and `HEAD` with the working tree. It fails when a
scored pattern (listed in `initial_core`, declaring `status: core`, or, with `--measurements`,
effective core on the base commit) loses its file at its path (deleted, renamed, moved) or
changes `id`, `status`, `modality` or `detector.kind`: the gates skip deleted files, other
modalities and detectors they cannot run. A change that also touches `governance/` needs
code-owner review, so the guard then reports these findings as notices and passes.

## 7. Skill package constraints

The package must satisfy the strictest known runtime (Gemini app, Nov 2026):

- Folder name equals skill name `slop-check`; `SKILL.md` in the package root with frontmatter `name` (lowercase, hyphens) and `description` of at most 200 characters (claude.ai's limit, the strictest known; it states the situations in which the skill applies, and runtimes auto-trigger on it).
- Two archives: `slop-check.zip` with the folder `slop-check/` at its root (Claude, Gemini) and `slop-check-flat.zip` with `SKILL.md` at its root (runtimes that expect that, such as Microsoft 365 Copilot and Copilot Studio).
- Allowed file types only: `.md`, `.py`, `.json`, `.yaml`, `.txt`. No archives inside, no hidden files, no `__pycache__`/`.pyc`, total size far below 100 MB.
- Scripts must not need network access. The engine runs fully offline; `--llm` is a CLI feature outside skill mode.
- At most 200 files per archive (claude.ai rejects larger ones, community report). `check_package` counts
  every file and folder plus the root folder, which is the number of zip entries (`MAX_FILES`).
- Three archives, one package: `slop-check.zip` (folder `slop-check/` at the root; Claude, Gemini CLI),
  `slop-check-flat.zip` (`SKILL.md` at the root; Microsoft 365 Copilot, Copilot Studio) and
  `slop-check-lite.zip` (`SKILL.md` and `references/*.md` at the root, no `scripts/` and no
  `references/scripts-usage.md`; Gemini app, Microsoft 365 Copilot Cowork, Vibe Work, which run no
  scripts or accept at most 20 companion files). `check_package(..., lite=True)` enforces no `scripts/`
  and at most 20 files besides `SKILL.md`. All three carry the same `SKILL.md`; its script step is
  conditional ("if `scripts/slopcheck.py` exists and you can run commands").
- The packaged `SKILL.md` must be sufficient on its own for a correct audit. Some hosts load only
  `SKILL.md`: the Gemini app runs no bundled scripts and opens reference files only on demand, and a
  model that found neither wrote a free-form critique without pattern IDs, score or verdict
  (observed 2026-11-17). So `SKILL.md` states first that the skill works fully without code, puts the
  manual audit first and the script in an optional step after it, never lets the model mention a
  missing script or file, and carries the report skeleton with English and German labels. Each
  reference is named with an imperative and its base name as well (`references/text-patterns.md`
  (`text-patterns.md`)) for hosts that flatten folders. The build guarantees the pattern part:
  `skill/SKILL.md` holds the lines `<!-- slopcheck:core-catalog -->` and `<!-- /slopcheck:core-catalog -->`
  with a placeholder between them, and `slopcheck-dev build` replaces that region in the packaged copy
  with the catalog version, the verdict thresholds and their source, whether weights are provisional,
  one line per scored text pattern (ID, name, weight, how to find hits, threshold as the report writes
  it, typical hits per language: the matched part of the positive examples for phrase patterns, the
  first word-list terms for word lists, short examples for the others) and one line of candidate and
  fading IDs. The region is generated from the compiled catalog, so it follows every measurement. The
  build fails when the marker pair is missing or malformed.
- Size of the packaged `SKILL.md`: at most 500 lines and about 5,000 tokens (Agent Skills guidance),
  estimated as characters ÷ 4 (`MAX_SKILL_LINES`, `MAX_SKILL_TOKENS`). The build takes the richest
  core list that fits (two typical hits per language, then one, then none) and warns when it had to
  reduce it; it fails only when even the list without typical hits does not fit, and then the
  hand-written text of `skill/SKILL.md` must get shorter. A measurement that promotes more patterns to
  core therefore shrinks the list instead of breaking the release. The build prints the size.
- `exports/instructions.md` must fit an instruction field: at most 7,500 characters
  (`MAX_INSTRUCTIONS_CHARS`), with the same fallback (three key phrases per pattern, then two, one,
  none) and a build failure beyond it. `exports/system-prompt.md` replaces the core-catalog region by a
  pointer to its condensed catalog, so it lists each pattern once.

## 8. Workflows

| File | Trigger | Privileges | Purpose |
|------|---------|------------|---------|
| `ci.yml` | `pull_request`, `push` to main | read-only, no secrets | lint, tests, validate, scored-pattern guard (`slopcheck-dev guard`), fixtures, deterministic empirical gate (dev split), build check, dogfood; final job `ci-gate` |
| `llm-eval.yml` | `workflow_run` of ci (completed with success) | secrets, trusted code from main only | LLM gate for changed `llm` patterns; fetches PR files via API at the head SHA, treats them as data; posts commit status `llm-gate` |
| `automerge.yml` | `pull_request_target` | `contents: write`, `pull-requests: write`; never checks out PR code | enables auto-merge (squash) only for content-only PRs into `main`; labels PRs touching protected paths `needs-owner` and withholds auto-merge from them |
| `measure.yml` | monthly schedule (daily in the first week until the month is measured), dispatch | secrets in a read-only job; a separate job without them writes to `data` | corpus refresh, full holdout measurement, report, issue |
| `conformance.yml` | monthly schedule (daily in its first week until the month has a result), dispatch, push to main touching `skill/` | secrets in a read-only job; a separate job without them writes to `data` | skill conformance across model families |
| `release.yml` | push to main, dispatch, tags `v*` | write to `dist`, releases | build package with current measurements, publish |
| `models.yml` | weekly schedule, dispatch | write to `data`, no secrets needed | resolve model selectors against OpenRouter, commit `models/lock.json` |

Required status checks on `main`: `ci-gate`, `llm-gate`. Code owner review required;
required approvals otherwise 0. Setup steps: `docs/maintainers.md`.
