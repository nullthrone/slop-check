# Corpora for measurement

The empirical gate (docs/architecture.md, section 6) compares how often a pattern triggers in
human text written before LLM assistants became common with how often it triggers in text
generated by current models. This directory holds the specifications. No human text is ever
committed: `slopcheck-dev corpus fetch-human` downloads the documents at run time into a local
directory, and only `manifest.json` (references and SHA-256 hashes) goes to branch `data`.

## Human corpus

Specification: [`human.yaml`](human.yaml). Cutoff: nothing published on or after 2022-11-01
(the public release of ChatGPT was on 2022-11-30). Every source below predates that by at least
eleven months; the web sources are restricted further, to pages crawled before June 2020, when
the GPT-3 API opened and the first generated marketing copy started to appear on the open web.

All rows come from the Hugging Face datasets-server JSON API
(`https://datasets-server.huggingface.co/rows?dataset=...&config=...&split=...&offset=...&length=...`),
so no parquet reader is needed. Sampling draws offsets from a PRNG seeded with `seed` and the
source id, which makes the selection reproducible for a given dataset state. The API always serves
the current dataset revision, so each source pins the Hub commit it was chosen at, and
`fetch-human` records the commit it actually saw next to the pin. `--strict-revision` turns a
mismatch into an error. The SHA-256 of each document in `manifest.json` lets later runs detect any
change in the underlying rows.

Why these registers: web prose from Common Crawl contains the marketing pages, shop texts, news
items and blog posts that generated text now imitates. Wikipedia covers neutral expository
writing. Forum answers cover explanations written for a specific asker, which is the register of
assistant replies.

Per language the default specification yields 260 documents (110 web, 75 encyclopedic, 75 Q&A).
The split rule `sha256(doc_id) % 10 < 5` puts about half of them in `dev` and half in `holdout`,
which leaves more than the 100 documents per language that `admission.core` requires on holdout.

### Filters

Applied in this order, for every source:

1. Adapter: `fineweb` turns each line into a paragraph (the extractor emits one block element per
   line) and applies `max_date`; `wiki40b` decodes the dataset's section and paragraph markers and
   uses the article title; `mqa` takes the accepted answer, else the longest answer, drops answers
   with fenced code, removes image markup and link targets, and uses the question title.
2. Mojibake: documents containing U+FFFD are skipped.
3. Language: a stopword check rejects rows whose text is in another language (the MQA English
   configuration contains Russian and Spanish pages, for example).
4. Prose: letters must make up at least 85 % of the non-space characters, which removes formulas,
   code and markup dumps.
5. Repetition and tables: pages built from repeated sentences or dominated by table rows are
   skipped.
6. Length: 150 to 1200 words (Unicode word tokens). Wikipedia articles longer than 1200 words are
   cut at a paragraph boundary instead of being dropped, so long articles are not lost.
7. Diversity: `max_per_domain` limits documents per web domain; exact duplicates are dropped.

### Known biases

- Common Crawl and forum text was converted from HTML. It has no Markdown, so patterns that look
  at Markdown markup (bold lead-ins, emphasis density, emoji bullets) see almost no human hits,
  which inflates their lift. Their gate results deserve a second look before promotion.
- Wikipedia articles cut at 1200 words have no natural ending, which can lower the human rate of
  patterns that inspect the last paragraph.
- Some German web pages in Common Crawl were machine translated before 2020 (statistical or
  early neural systems). They stay in the corpus: they predate LLM text, and real readers meet
  them too.

## AI corpus

Prompts: [`prompts/en.yaml`](prompts/en.yaml) and [`prompts/de.yaml`](prompts/de.yaml).
`slopcheck-dev corpus generate-ai` pairs every human document with one prompt (chosen from the
prompts whose `human_registers` contains the document's register, by hash of the document id),
fills in a topic and a target length, and sends it to every generator in `models/lock.json`.

- Topic: the document title if there is one, else its first line when that is 2 to 20 words long,
  else its first sentence shortened at a clause boundary. URLs, e-mail addresses, handles and phone
  numbers are removed. No LLM is involved.
- Target length: the human document's word count rounded to tens, clamped to 150 to 1200.
- Selection: each generator takes the first `docs_per_language` documents of one fixed order
  (sorted by a hash of the document id), so cheaper and more expensive models share topics.
- Output: `<out>/<canonical_slug with "/" replaced by "__">/<lang>.jsonl.gz`, one JSON object per
  line with `doc_id` (the paired human document), `model`, `canonical_slug`, `family`, `tier`,
  `language`, `register`, `human_register`, `prompt_id`, `topic`, `target_words`, `words`,
  `usd` and `text`.

The prompts carry no style instructions. They read like everyday requests, because the corpus has
to show what each model writes by default. Reasoning is set to the lowest effort a model accepts
(from the `reasoning` object in `/api/v1/models`) to keep cost down.

When a generator's `canonical_slug` changes in the weekly lock, the next run writes a new
directory for it. Old directories stay for trend reports; `slopcheck-dev measure --lock-filter`
measures only models that are in the current lock.

## Commands

```
slopcheck-dev corpus fetch-human --out .corpus/human
slopcheck-dev corpus generate-ai --human .corpus/human --out .corpus/ai --lock models/lock.json
slopcheck-dev measure --human .corpus/human --ai .corpus/ai --split holdout --out .eval-out/measurements.json \
    --report .eval-out/report.md --lock-filter --lock models/lock.json
```

`.corpus/` and `.eval-out/` are listed in `.gitignore`.
